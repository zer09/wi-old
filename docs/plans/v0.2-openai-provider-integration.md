# Wi v0.2 — OpenAI provider integration plan

Status: architecture frozen; Milestone 11 implementation candidate complete and pending release review; Milestone 12 not started

Date: 2026-07-29

Baseline: released `v0.1.0-vertical-slice` at `1c0689896b27c046b8b9a392251f6885e715515a`

Scope: Milestones 10–17, implemented and reviewed one milestone at a time

## 1. Truthful product baseline

The released baseline implements the v0.1 vertical slice:

- local, single-operating-system-user, Linux-only backend;
- disposable browser GUI over HTTP and one multiplexed `wi.v1` WebSocket;
- backend-owned durable runs and replay;
- one canonical SQLite database per session plus a rebuildable catalog;
- deterministic fake provider only;
- safe built-in test tools only;
- commit-before-publication, idempotent commands, terminal-response tool promotion, and the durable tool ledger.

The Milestone 11 candidate additionally implements fake/no-network provider connections, protected local API-key credentials, read-only environment references, multiple explicit connections, durable lifecycle/recovery, capability snapshots, and immutable run selection snapshots. It does **not** implement OpenAI requests, ChatGPT/Codex OAuth, live capability discovery, provider WebSocket transport, automatic routing, real project tools, CodeGraph, Context Mode, or plugins.

This plan defines v0.2 architecture and sequencing. Behavior after Milestone 11 remains marked as required, deferred, or optional after its gate.

## 2. Objective

Add direct OpenAI providers without reopening the foundational questions of account identity, billing visibility, credential storage, run ownership, provider state portability, cache affinity, and fallback.

The implementation must preserve every accepted v0.1 invariant and [ADR-0005](../adr/0005-direct-provider-adapters.md)/[ADR-0006](../adr/0006-no-app-server-fallback.md): Wi remains the only harness and never invokes `codex app-server`.

## 3. Frozen v0.2 decisions

The authoritative detail is in [the provider-connections architecture](../architecture/v0.2-provider-connections.md) and ADR-0013 through ADR-0017.

1. **Multiple connections:** Wi is required to support several simultaneous connections for the same provider/auth mode.
2. **Separate auth/billing modes:** `openai_platform + api_key` and `openai_codex + chatgpt_oauth` are distinct connection types.
3. **Explicit selection first:** the only active policy through Milestone 14 is an explicit `connectionId`.
4. **Run pinning:** accepted runs snapshot connection, credential generation, account/workspace, model, capabilities, prompt/tool/reasoning/transport, and provider-chain identity.
5. **Provider-chain isolation:** account changes create a new chain; opaque cursors/state do not cross by default.
6. **Cache affinity:** affinity includes connection, model, prompt, tool schema, chain, and transport.
7. **CredentialStore:** the default v0.2 backend is a protected plaintext file store outside `WI_HOME`; environment API-key references are read-only; keyring is optional later.
8. **Capabilities:** models and transport/reasoning/tool/cache support are discovered per connection, not from a static global list.
9. **Transport order:** Responses HTTP/SSE precedes provider WebSocket optimization.
10. **Routing gate:** automatic routing is optional, telemetry-gated, opt-in, and prohibited mid-run.
11. **Source freeze:** later implementation is reviewed against [the source snapshot ledger](../reference/source-snapshots.md); upstream changes are not silently adopted.

## 4. Cross-milestone invariants

All v0.1 hard invariants remain in force. v0.2 additionally requires:

- provider connections are isolated by stable `connectionId`;
- active runs are pinned to connection and credential generation;
- no silent provider/account/workspace/auth-mode/model/endpoint/transport/billing switch;
- provider secrets stay outside catalog/session SQLite and browser payloads;
- file credentials stay outside `WI_HOME` and its backup/export boundary;
- explicit selection is the only active routing policy until a later accepted gate decision;
- opaque provider state is non-portable across connections by default;
- connection-specific capabilities used by a run are snapshotted at acceptance;
- no provider continuation can bypass ADR-0007 or the durable tool ledger;
- provider network I/O remains asynchronous control-plane work; synchronous SQLite, CPU-heavy work, and plugins remain off the main event loop;
- browser disconnect never cancels provider work.

## 5. Planned package direction

Milestone 10 creates no packages or production code. Later milestones should preserve existing dependency direction and introduce the smallest packages justified by implementation.

Expected responsibilities, without freezing premature filenames:

```text

  provider-neutral requests/events/state/capabilities/router-facing snapshots

  nonsecret catalog records, lifecycle, explicit selection, capability metadata

  CredentialStore interface, file/environment backends, OAuth attempt state

  API-key auth, Responses HTTP/SSE, normalized events

  OAuth identity/refresh, direct supported Responses surface, capabilities

  run acceptance pinning, provider-chain identity, canonical request rebuild

```

No domain package may import Fastify, React, SQLite-driver, or worker implementation types. Detailed package creation is a Milestone 11 implementation decision constrained by the accepted ADRs.

## 7. Milestone 11 — Provider connections and credential store

Status: implemented in the current fake/no-network candidate; pending independent release gates and not yet part of the released v0.1 baseline.

### Scope

```text
catalog provider-connection metadata
file CredentialStore with backend-only API-key staging/provisioning
read-only environment API-key references with pre-acknowledgement run leases
multiple same-provider/auth-mode connections
connection create/list/rename/disable/logout/delete lifecycle
nonsecret cross-store lifecycle operation and restart reconciliation
connection-management browser protocol and UI from the frozen operation inventory
session default connection/model selection
explicit router only
run acceptance snapshots and providerChainId
capability snapshot storage boundary without OpenAI network discovery
redaction, permission, containment, restart, and export/backup tests
```

There are no OpenAI network requests, provider endpoint probes, OAuth exchanges, or live capability discovery in Milestone 11. Connection and capability behavior uses deterministic fake/no-network fixtures only.

### Required behavior

- second same-provider connection does not overwrite the first;
- simultaneous duplicate proven account/workspace logins atomically resolve one winning `connectionId` through a normalized catalog uniqueness claim;
- connection operations are independently idempotent through one durable per-connection lifecycle owner spanning catalog prepare, the one-connection file effect, and terminal catalog commit;
- create/replace/relogin/reauthenticate/refresh-publication/disable/logout/delete are mutually exclusive; identical retries resume, while a conflicting command receives one stable `operation_in_progress` result and is never queued automatically;
- lifecycle revisions increment once at cutoff prepare or catalog-only disable/enable, remain monotonic through tombstones, and are distinct from alias/capability/rate metadata revisions that cannot close or reopen leases;
- recovery terminalizes a nonterminal owner before another lifecycle operation; unprovable post-effect terminal state remains unavailable with evidence preserved and cannot resurrect credentials;
- a backend-local masked-stdin/file-descriptor provisioner durably stages file API keys outside `WI_HOME`, returns only a one-time opaque reference, and owns expiry/cleanup;
- identical command retries after any crash boundary return one stable result without incrementing generation twice;
- run acceptance commits its provider snapshot before acknowledgement; environment-backed acceptance first resolves and fingerprints the value in a process-scoped lease;
- changing a session default cannot mutate an active run;
- a provider request leased before committed disable/logout may settle, but no new request, refresh, or post-tool continuation starts after the cutoff;
- file root is external to `WI_HOME`, `0700`; files are `0600`;
- staging and final writes are bounded, flushed, atomic, and independently serialized/claimed;
- a verified current-user-owned, single-link existing credential file with only an unsafe mode is repaired to `0600`, flushed, and revalidated before secret read;
- symlink/path escape, aliases into `/mnt/c` or Windows-backed mounts, unsupported filesystem semantics, and envelope/catalog identity mismatch fail closed;
- environment variables resolve at acceptance and every request; replacement/disappearance before the first or later request fails the accepted run, and restart interrupts when its nonpersisted fingerprint cannot be reconstructed;
- credential material is absent from catalog/session DBs, browser payloads, logs, diagnostics, fixtures, and exports;
- complete catalog loss preserves credential files without auto-import; only a complete bounded closed scan of the managed root exposes safe metadata plus opaque one-time `recoveryRef` values, while cap exhaustion, root change, or duplicates issue no claimable references;
- recovery references are process/scan-epoch bound and memory-only in the browser; before send, only safe `commandId`/operation-kind/nonclaiming-epoch/expiry/expected-display metadata enters a separate reconciliation journal, never the complete command or reference;
- command ingress synchronously registers with a bounded epoch admission coordinator and durably records reference-free phase `validating` before the pre-prepare scan; restart from `validating` terminalizes stable `recovery_ref_expired`;
- browser status reports admission/open-epoch/`validating` as pending, and reports final `not_accepted` only after the epoch closes and every registered ingress drains, proving the old command cannot later prepare; terminal returns the original result;
- recovery transitions `validating` through a repeated complete scan to one exact claim/`prepared`, restores only the envelope's original `connectionId` and generation, checks its persisted authoritative subject/account/project/workspace identity or preserves explicit unverified status, and rejects arbitrary refs/paths;
- connection-ID/identity conflicts and malformed/mismatched/changed/already-claimed evidence remain preserved; a post-claim source change leaves an unavailable original-identity tombstone whose next transition is normal explicit replacement/reauthentication, not another interpretation of the evidence;
- recovery interrupts pre-loss nonterminal provider work and never persists a credential-derived fingerprint.

### Minimum tests

- unit/property tests for normalized atomic identity claims, aliases, lifecycle, generations, router selection, envelope validation, and path generation;
- storage integration tests for nonsecret operation metadata, identity conflicts, stable command results, and transactional run snapshots;
- process tests killing before/after stage commit, catalog prepare/claim, file publish/delete, terminal catalog commit, acknowledgement, and stage cleanup, plus noninteractive WSL/Linux restart and Windows-mount rejection; the direct Milestone 11 namespace boundaries are `after_provider_credential_rename_before_flush` (exit 114), `after_provider_credential_unlink_before_flush` (exit 115), and `after_provider_stage_rename_before_flush` (exit 116), all gated by the closed test-only failpoint controller;
- property/process interleavings for replace/disable, replace/logout, delete/reauthenticate, refresh/logout, and two distinct replacements at every prepare/file/terminal/acknowledgement boundary, asserting one owner/generation/result and no resurrection or cross-connection mutation;
- metadata concurrency tests proving rename/capability/rate updates use disjoint revisions and cannot overwrite lifecycle ownership, administrative cutoff, generation, or lease state;
- lease-boundary tests for disable/logout before request, during stream, after provider completion, after tool result, and before continuation;
- environment tests replacing/removing the value between acceptance and first request, on later steps, and across restart, with exact no-use/no-fallback assertions;
- existing-file `0644` repair-before-read tests plus symlink/owner/hard-link/substitution controls;
- protocol/UI tests for every applicable operation-inventory row, explicit selection, duplicate command IDs, browser disconnect, and secret-free payloads;
- catalog-loss recovery tests with several envelopes, same aliases/different identities, authoritative/unverified identity claims, original-ID and authoritative-identity conflicts, duplicates beyond page boundaries, incomplete/truncated/changing scans, malformed/mismatched/changed/already-claimed evidence, arbitrary refs, and unavailable-tombstone reprovisioning;
- leakage tests seed generated filenames, internal credential references, recovery references, and credential-derived hash canaries; permit a recovery reference only in its bounded candidate response/in-memory matching command, and prove absence from unrelated payloads, persistent browser storage/history, URLs, logs, diagnostics, traces, fixtures, and exports;
- recovery process tests killing before claim (stable stale-reference failure after restart) and after exact claim, file observation, terminal catalog commit, and acknowledgement, proving original connection/generation restoration, one claim/result, and preserved evidence;
- combined browser/process tests lose acknowledgement during pre-admission ingress, `validating` scan, after `prepared`, and after terminal commit; reload/close/reopen with no persisted reference and reconcile by safe command identity to pending/not-accepted/original result with no second claim, row, generation, or credential effect;
- command-status tests race lookup against pre-prepare scan completion, prove open epoch cannot return final absence, prove closed epoch plus drained ingress cannot later prepare, and cover same-ID epoch/metadata conflict, already-claimed evidence, bounded authenticated repeated reads, browser reconnect/status events, and no mutation/execution/reference exposure;
- secret-scanning and permission/export boundary tests.

### Exit gate

All connection/credential behavior works with fake/no-network adapter fixtures. No OpenAI endpoint is contacted.

## 9. Milestone 13 — ChatGPT/Codex multi-account OAuth

Status: required after Platform HTTP/SSE stabilizes.

### Scope

```text
multiple simultaneous openai_codex connections
browser PKCE flow
device-code flow
independent durable OAuth attempts
single-flight refresh per connection
subject/account/workspace identity binding
workspace selection
connection-specific capabilities/models
logout, deletion, reauthentication, and generation changes
no billing/account fallback
```

### Required constraints

- two attempts cannot cross-complete;
- callback state and PKCE values stay outside browser/catalog/session storage;
- duplicate callback is one-time/idempotent;
- denial, cancellation, expiry, mismatch, and restart are explicit states;
- simultaneous completion for the same account/workspace resolves atomically to one connection and returns that stable identity to both attempts;
- same account in two workspaces may create two explicit connections;
- refresh token replacement affects one connection only and preserves generation only for verified unchanged identity;
- OAuth start/cancel/status, workspace selection, callback/device ownership, and reauthentication follow the frozen browser/protocol operation inventory;
- provider-required callback query/form parameters use only the dedicated bounded no-store/no-referrer endpoint and are immediately replaced by a clean expiring tombstone without persistence or forwarding;
- callback and tombstone inherit exact-loopback single-Host validation and reject missing/duplicate/malformed/nonmatching Host before parsing; request method/mode, target, headers, fields, body, content type, and parser work are bounded;
- WebSocket Origin policy and Wi browser cookies are not callback authorization: absent/cross-site Origin and missing/stale/unrelated cookies neither authorize nor reject, while exact attempt `loginId`/state/PKCE/expiry/redirect contract authorizes one completion across restart;
- no Platform fallback and no `codex app-server`.

### Exit gate

Mocked OAuth and provider tests demonstrate simultaneous same-identity completion, same-subject/different-workspace control, attempt status across browser disconnect, callback history/referrer/storage/log/network containment, exact/missing/duplicate/malformed/wrong Host handling, absent/cross-site Origin, missing/stale/unrelated cookies, parser/field/body bounds, duplicate completion, multi-account isolation, restart, refresh, workspace binding, reauthentication, redaction, and explicit billing identity. Any live test follows the trusted-environment gate in Section 17.

### Gate

After representative Platform and ChatGPT/Codex operation, make an explicit go/no-go decision. Record it in a new ADR or amendment.

A future opt-in `AffinityAwareProviderRouter` is allowed only if evidence shows a concrete Wi requirement and the design preserves:

- selection before a new run/provider chain only;
- no mid-run switch;
- no switch after semantic output or tool effect;
- explicit cross-auth/billing pool opt-in;
- durable routing/fallback decisions;
- visible account/workspace/billing identity;
- affinity over naive round-robin;
- no hidden fallback.

Automatic routing is not presumed mandatory for v0.2.

## 15. Credential acceptance matrix

| Scenario | Required outcome |
|---|---|
| Stage file API key | Backend-only complete stage or no returned reference; unclaimed expiry and claimed restart recovery are deterministic. |
| Create root/file | Exact `0700`/`0600` modes. |
| Existing owned file becomes `0644` | No-follow descriptor validation, repair/flush/revalidation to `0600`, then secret read. |
| Replace unsafe file | Replacement repairs `0600`. |
| Symlink or path escape | Reject before secret read/write. |
| Crash during replacement | Old complete or new complete envelope, never partial JSON. |
| Missing environment key at acceptance | Run is rejected before acknowledgement; no fallback. |
| Environment key changes acceptance→first request or later | Pre-acknowledgement-pinned run rejects the changed value before use. |
| Backend restarts with accepted environment-backed run | Run interrupts before provider work because the fingerprint is nonpersisted. |
| Noninteractive WSL restart | File credentials load without keyring/GUI dependency. |
| Stopped `WI_HOME` backup | Credential root is not included. |
| Complete catalog loss with several credential files | A complete bounded scan returns only safe metadata and opaque one-time recovery references; cap exhaustion, root change, or duplicate identity issues no claimable references and never auto-imports. |
| Same alias, different envelope identities | Alias has no recovery identity authority; each otherwise unique candidate remains independently selectable. |
| Authoritative versus unverified recovery identity | Subject/account/project/workspace claims conflict fail closed; `unverified` remains distinct only by original `connectionId` and is never guessed or deduplicated. |
| Explicit orphan recovery | One command claims one exact envelope and restores its original `connectionId`/generation; lifecycle revision starts at 1 for the rebuilt catalog epoch. |
| Arbitrary or unissued recovery reference | Reject as `recovery_ref_invalid`; no candidate, claim, path lookup, or catalog row is created. |
| Command ingress/status race before durable admission | Registered ingress or open epoch returns pending; final `not_accepted` waits for epoch closure and drained ingress, after which the old command cannot prepare. |
| Backend restart from durable `validating` before recovery prepare | Process-bound reference is gone; accepted command terminalizes stable `recovery_ref_expired`, and status returns that original result. |
| Reload while pre-prepare complete scan is running | Safe epoch/command entry survives; status returns `validating` pending and cannot discard the identity before prepare/failure. |
| Prepared recovery acknowledgement lost, then page reload | Only safe reconciliation metadata survives; command-status returns pending while backend recovery continues, with no resend or second claim. |
| Terminal recovery acknowledgement lost, then page reload | Reference-free command-status returns the original durable safe result exactly once to the browser. |
| Crash after recovery prepare/file observation/terminal commit | In-memory identical retry or reference-free status reconciliation yields one stable result; no duplicate connection or claim. |
| Recovery status absent after epoch closure/drain | Final `not_accepted` discards the safe entry and requires fresh scan/new ID; the old command cannot later claim. |
| Recovery status method/epoch/metadata conflicting | Return typed conflict without mutation or disclosure. |
| Recovery source changes after claim | Terminalize an unavailable original-identity tombstone and consume the claim; only normal explicit replacement/reauthentication may proceed. |
| Recovery connection/identity/already-claimed conflict | Fail closed with preserved evidence and one stable result; never expose a path/secret or create a duplicate connection/claim. |
| Delete A | Only A's file/ref is deleted. |
| Secret scan | No key/token in browser, SQLite, logs, diagnostics, exports, or fixtures. |

## 17. Validation strategy

Every implementation milestone must add tests before or alongside behavior and run its narrow suites repeatedly. Before completion it must run:

```text
pnpm lint
pnpm typecheck
pnpm test:unit
pnpm test:integration
pnpm test:property
pnpm test:process
pnpm test:e2e
pnpm build
pnpm check
```

Provider milestones also require:

- deterministic mock HTTP/SSE/OAuth/WebSocket servers;
- no-network tests by default;
- opt-in live smoke tests with explicit connection/account/billing visibility;
- live tests disabled on forks and untrusted pull requests, with credentials available only to an explicit trusted local or manually approved environment;
- redaction scans using synthetic non-production secrets;
- process restart/crash tests for credential and provider-state boundaries;
- property tests for identity deduplication, generation pinning, routing policy, and cache/state non-portability.

A milestone is not complete because code compiles. Its architecture cases and exit gate must pass.

## 18. Source-freeze policy

During v0.2 implementation:

1. evaluate behavior against [the frozen ledger](../reference/source-snapshots.md);
2. track later upstream changes only in the watchlist;
3. do not silently adopt a newer provider/auth/transport behavior;
4. after provider/authentication milestones stabilize, compare frozen and current sources;
5. classify security, protocol, useful, and breaking changes;
6. adopt only changes solving a concrete Wi requirement;
7. preserve backend ownership, account/billing identity, durable events, tool-effect rules, and no-fallback decisions;
8. record adopted changes in an ADR or compatibility note.

## 19. Explicit implementation exclusions for Milestone 10
